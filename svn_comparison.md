
1. Ветвление: Git дёшево, SVN дорого
   Git: ветка = файл с хешем коммита (~40 байт). Создание — мгновенно, локально, без сети. Вся история — граф коммитов, ветки просто указывают на узлы.

SVN: ветка = копия директории в репозитории (даже с "cheap copy" в FSFS — это серверная операция + коммит + сетевой round-trip). Мержи отслеживаются вручную через svn:mergeinfo.

Итог: в Git ветка — ссылка, в SVN — объект репозитория.

2. Коммит в SVN без интернета
   Нельзя. SVN централизован: коммит = создание новой ревизии на сервере. Офлайн работают только status, diff, revert. В Git коммит — локальная запись в .git/objects, сеть нужна только для push/pull.
3. Где SVN ещё предпочтительнее
   Большие бинарники (CAD, видео, арт) — SVN хранит их нативно, в Git нужен LFS.

Тонкие права по путям — authz на подкаталоги; в Git права только на весь репозиторий.

Частичный checkout — --depth в SVN проще, чем sparse-checkout/partial clone в Git.

Централизация и аудит — монотонные номера ревизий, единая точка, простой бэкап.

Legacy и не-программисты — старые CI, TortoiseSVN, линейная модель без хешей.
